# F21 — BONO + LIQUIDACIÓN CONTRACTUAL

## 3. Objetivo

Cerrar un arrendamiento con una liquidación auditable basada en las autoridades existentes, sin recrear cartera, pagos, inventarios, documentos, membresías o lifecycle del lease.

El bono de buen cumplimiento es un concepto contractual separado. No es depósito, garantía retenida, cargo negativo, pago ni membresía.

La liquidación es un **snapshot de cierre**, no un segundo sistema financiero.

## 5. good_conduct_bonuses

Una sola fila potencial por lease.

Modelo mínimo:

```text
id BIGINT UNSIGNED PK
lease_id BIGINT UNSIGNED NOT NULL UNIQUE
amount DECIMAL(12,2) NOT NULL
note VARCHAR(1000) NULL
decision VARCHAR(16) NULL
created_by_user_id BIGINT UNSIGNED NOT NULL
created_at DATETIME NOT NULL
updated_at DATETIME NULL
decided_by_user_id BIGINT UNSIGNED NULL
decided_at DATETIME NULL
```

FKs:

```text
lease_id -> leases RESTRICT
created_by_user_id -> users RESTRICT
decided_by_user_id -> users SET NULL
```

Reglas:

- `amount > 0`;
- `decision` solo `approved|denied|null`;
- `null` = pendiente, derivado; no columna `status`;
- amount/note pueden corregirse solo mientras `decision IS NULL`;
- `approved|denied` es terminal;
- una decisión terminal no se reabre;
- no se crea charge, payment, refund, credit ni accounting entry;
- no se descuenta automáticamente de cargos existentes;
- si no existe fila, el lease no tiene bono configurado.

### Feature gate

El bono permanece desactivado por defecto hasta aprobación contractual explícita.

Una sola bandera de configuración simple:

```text
GOOD_CONDUCT_BONUS_ENABLED=false
```

Cuando está desactivada:

- no se muestran mutaciones del bono;
- no se crean filas nuevas;
- la liquidación registra `bonus = null`.

No crear tabla de reglas, scoring, eligibility engine o CMS de bonos.

FKs:

No `status`, `draft`, `updated_at`, tabla de items ni tabla de versiones.

La ausencia de fila significa “no finalizada”. La presencia de fila significa “finalizada”.

La fila es append-once: no update/delete funcional después del insert.

## 7. Preview derivado

No se persisten borradores.

`TerminationService::preview(leaseId, today)` deriva un preview actual desde autoridades reales.

Debe incluir, cuando aplique:

```text
lease + contract identity/dates
finance summary + charge states
pending/reconciled payment context necesario
F12 obligations/services
F13 claims/policies relevantes
F18 initial/final inventory document ids
F18 current final lease documents
F19 community incidents relevantes
F20 memberships + terminal charge decision state
F21 bonus state
handover input temporal: entrega física, cantidad de llaves, nota de entrega
```

Reglas:

- no copiar contenido binario de documentos;
- no copiar documentos completos dentro del snapshot;
- guardar ids, hashes/fechas/títulos seguros y valores necesarios para evidencia;
- no duplicar cálculo de cartera: usar `FinanceService`;
- no duplicar inventario: usar `DocumentService`;
- no duplicar membership billing: usar `MembershipService`/F20;
- incidentes/reclamaciones abiertos se muestran y se snapshottean, pero no crean un nuevo workflow F21.

## 8. Relación con LeaseService

`LeaseService::end()` continúa siendo la única operación que termina el lease.

Flujo canónico:

```text
staff reviews derived preview
→ explicit existing LeaseService::end()
→ lease is ended
→ final liquidation may be created
```

`TerminationService`:

- nunca escribe `leases.ended_at`;
- nunca cambia unit status;
- nunca activa/desactiva tenant auth;
- nunca llama una terminación paralela.

### Precondición fuerte

`finalizeLiquidation()` requiere `lease.ended_at IS NOT NULL`.

No se finaliza liquidación de lease activo.

---

## 9. Bloqueos antes de finalizar liquidación

El cierre debe fallar de forma segura si existe ambigüedad financiera/documental crítica.

Bloqueos mínimos:

```text
lease no terminado
payment report pendiente de reconcile/reject
paid F20 membership con charge_decision pendiente
bonus existente con decision pendiente
initial inventory existente pero final inventory inexistente
liquidation ya existente
```

No bloquean por sí solos:

```text
outstanding balance > 0
open community incident
open insurance claim
open maintenance history
```

Esos elementos se incluyen en el snapshot para mantener evidencia de cierre.

## 11. Bono dentro de la liquidación

Si existe bono aprobado:

```text
snapshot.bonus.decision = approved
snapshot.bonus.amount = exact approved amount
```

Si existe bono negado:

```text
snapshot.bonus.decision = denied
snapshot.bonus.amount = 0.00 informational projection
```

Si no existe bono o feature está desactivada:

```text
snapshot.bonus = null
```

F21 **no** calcula un pago saliente, no genera charge negativo y no crea refund.

Los saldos financieros y el bono se muestran como componentes separados del cierre. Cualquier movimiento monetario real posterior usa la autoridad financiera existente o queda fuera de V1.

Una API explícita y pequeña:

```text

  ?int actorUserId,
  string action,
  string entityType,
  ?int entityId,
  string summary,
  ?string remoteIp,
```

Reglas:

- action/entity type allowlisted o formato machine-key estricto;

- metadata JSON máximo 2048 bytes;

AuditService no dispara dominio y no decide negocio.

## 22. Matriz obligatoria de hardening

F22 debe revisar y probar, no asumir:

### Público / catálogo

- solo allowlist pública;
- dirección/notas internas no se filtran;
- media de unidad despublicada devuelve 404;
- slug/public key no expone ids internos ni datos privados;
- headers seguros en respuestas públicas sensibles.

### Candidatos

- token solo hash en DB;
- expiración/rotación fail closed;
- candidato no enumerable;
- duplicate identity respuesta genérica;
- rate limits existentes preservados;
- logs no contienen raw token.

### Tenant / IDOR

Orden obligatorio:

```text
current user
→ LeaseService::findForUser()
→ only then child lookup
```

Aplicar a:

```text
finance
payments
obligations
maintenance/visits
documents
community
memberships
liquidation
```

No child lookup primero + ownership después.

### Uploads / storage

- private outside webroot;
- physical size before unbounded read;
- bounded reads;
- MIME from bytes;
- SHA-256 where current authority uses integrity hash;
- reject PHP/spoofed/unsupported;
- reject traversal;
- reject symlink;
- canonical path containment;
- `private, no-store` + `nosniff` on private file responses.

### Auth / session / CSRF

- same auth única;
- session id rotation on login;
- forced password change preserved;
- inactivity timeout preserved;
- CSRF on every authenticated state mutation;
- exact protected cron exemption only;
- no broad wildcard CSRF bypass;
- cookies/session production flags audited for HTTPS deployment.

### Errors / secrets / logs

- generic external 500/422 where required;
- no DB driver details;
- no SMTP password;
- no cron secret;
- no candidate token;
- no session/cookie dump;
- no document contents;
- `.env`/runtime storage inaccessible from web and ignored by Git.

### Redirects / external URLs

- preserve HTTPS validation where applicable;
- no user-controlled open redirect;
- WhatsApp assisted URL remains safe snapshot only;
- screening/provider external URL does not leak continuation token in referrer.

## 23. Security headers F22

Centralizar donde ya vive la respuesta/middleware común; no repetir headers ruta por ruta salvo private-file specifics.

