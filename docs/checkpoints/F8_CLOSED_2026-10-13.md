## Scope and architecture delivered

F8 adds the tenant lease portal using AlquilaPro's existing users, session, contracts, units, and private contract PDF authorities.

- **Persistence:** one `leases` table with `id`, `contract_id`, `user_id`, activation actor/time, and ending actor/time. It has a unique contract key, user/actor indexes, and foreign keys. There is no tenant table, lease-unit table, persisted lease status, or duplicated contract snapshot.
- **Identity and permissions:** a tenant is an existing `users` identity with role `tenant`. `Permissions` denies tenant administrative permissions; `UserService` creates a random temporary credential, stores only its password hash, and requires a password change. The credential is returned for one-time display after successful activation.
- **Activation:** `LeaseService` locks contract then unit in one transaction, validates the finalized contract/candidate/unit relationship and duplicate conditions, creates the tenant identity and lease, marks the unit occupied, and commits before returning the credential. Rollback covers all database writes.
- **Unit authority:** `PropertyService::updateUnit()` now starts or joins a transaction, locks the canonical unit row before checking active leases, and performs the guarded edit under that lock. It therefore serializes with activation and cannot overwrite `occupied` after activation commits.
- **Ending:** the service locks the lease and records `ended_by_user_id` and `ended_at` once. Ending does not release the unit or deactivate/delete the user; the existing unit editor remains the manual status authority.
- **Admin routes:** `POST /admin/contracts/{id}/lease` and `POST /admin/leases/{id}/end` use the existing session, forced-password, `contracts.manage`, and CSRF protections.
- **Tenant routes:** `GET /tenant`, `GET /tenant/leases/{id}`, and `GET /tenant/leases/{id}/contract` require the existing authenticated session and tenant role. Ownership is constrained in SQL; foreign or missing lease IDs return 404.
- **Private PDF:** the portal calls `ContractService::privatePdf()` after ownership succeeds, verifies PDF signature, byte length, and SHA-256, and returns private no-store/nosniff headers without exposing the stored filename.
- **Views and navigation:** output is escaped. The existing root route sends tenants to `/tenant` after the forced-password gate; the shared app shell points tenant Home there and omits Apps/admin navigation. Base-path handling is preserved.
