## Realidad integrada verificada

### FinanceService

El `FinanceService` integrado sigue siendo la autoridad financiera F9 y actualmente recibe solo `PDO`.

F11 debe extender esa misma autoridad; no crear `PaymentService`, `ReconciliationService` ni `AllocationService`.

### PaymentMethodService

F10 expone:

```text
listForProperty(int $propertyId)
find(int $id)
privateQr(int $id)
```

`listForProperty()` ya resuelve correctamente:

```text
is_active = 1
AND (property_id IS NULL OR property_id = canonical_property_id)
ORDER BY sort_order,id
```

RULING F11-PREFLIGHT-01:
F11 debe reutilizar esa autoridad para validar el medio activo/aplicable al reportar. No duplicar el algoritmo F10 con SQL lateral.

### Tenant ownership

`LeaseService::findForUser(leaseId,userId)` sigue siendo autoridad única de ownership.

RULING F11-PREFLIGHT-02:
Toda ruta tenant debe resolver ownership antes de payment/receipt lateral lookup.

### Private receipt storage

El bootstrap ya sigue patrón explícito de directorios privados (`contracts`, `payment-method-qrs`, etc.).

RULING F11-PREFLIGHT-03:
F11 puede añadir un único directorio privado `storage/payment-receipts` configurable por bootstrap e inyectarlo a `FinanceService` junto con `PaymentMethodService`.

Preferencia de constructor integrada:

```php
FinanceService(PDO $pdo, PaymentMethodService $paymentMethods, string $receiptDirectory)
```

Codex puede ajustar la forma exacta si demuestra una alternativa más KISS sin duplicar F10 scope ni crear clases nuevas.

### Migración


Por tanto:
